# FilamentVision v1.0.3 Real Image Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace all release fake inputs with a validated, persistent, configuration-driven real-image pipeline foundation that waits honestly for unimplemented device drivers while preserving real image processing and the existing monitoring data flow.

**Architecture:** Extend the existing single-runtime architecture with immutable profiles, a layered byte-to-measurement pipeline, an unavailable-driver production boundary, and real detection/fusion components. Reuse Room, alarms, trends, history, service lifecycle, and existing grayscale/threshold/edge processing.

**Tech Stack:** Kotlin, coroutines/Flow, Jetpack Compose, Room 2.8.4, Android SharedPreferences, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-09-30-v1-0-3-real-input-design.md`

## Global Constraints

- Release version is `1.0.3` with `versionCode = 103`.
- No release fake frame, detection, connection success, measurement, or simulation scenario.
- No unimplemented Bluetooth/Wi-Fi protocol may report connected or streaming.
- `MonitoringRuntime` remains the sole production measurement owner; `activeProducerCount <= 1`.
- Camera A and B raw measurements remain available before fusion.
- Realtime trend remains bounded to 300 samples.
- No CameraX, OpenCV, real radio/socket driver, WakeLock, WorkManager, or boot recovery is added.
- Every production behavior is introduced with a failing test first.
